## Source-of-Truth Rule

The TENSA website explains and teaches.

The GitHub repositories prove.

Do not treat TENSA website pages as the engineering source of truth.

Source-of-truth locations:

    NeuroCore repository
    Argus Lab repository
    future Argus ACLI source docs
    build logs
    architecture docs
    vision docs
    implementation docs

Website pages should translate, explain, organize, and route readers to deeper proof.

## Working Rules

Use full file replacements only.

Do not provide snippets unless explicitly requested.

After each full-file replacement, run a targeted verification check before moving to the next file.

Do not make hidden changes.

No changes the user does not know about.

Before replacing a file, inspect or request the current full file contents unless the file was generated in the same session and not changed afterward.

Do not guess.

If more context is needed, ask for the exact file or doc.

Use source docs before writing factual project pages.

Build one page at a time.

Keep the homepage as a front door.

Use project pages for major ecosystem explanations.

Use Knowledge Base pages for focused teaching articles.

Use Story pages for origin, philosophy, and ecosystem narrative.

Use Build Notes pages for readable development history.

GitHub remains the source of truth.

## Build-Start Checks

At the beginning of serious website build sessions, run:

    git status --short
    tree -a -I '.git|.obsidian|node_modules|__pycache__'
    find . -maxdepth 3 -name "*.html" -print
    grep -R "href=" -n index.html projects/*.html knowledge-base/*.html story/*.html

Future recommended replacement for manual link grep:

    scripts/check_internal_links.py

Purpose:

- confirm repository state
- confirm current tree
- confirm public page inventory
- confirm current links
- detect old navigation targets
- prevent broken links and drift
