# TENSA Engineering Repository Map

What each top-level directory is for. This page holds no file tree, no file counts and no per-file descriptions, and it must not grow them back: the repository shows its own contents. For a current file list, run `git ls-files`.

## Published to the website

- Repository root: `index.html` (homepage), `about.html`, `contact.html`, `styles.css` (the one stylesheet for the whole site), `favicon.ico`, `sitemap.xml`, `robots.txt` and `CNAME` (the custom domain).
- `projects/`: the Projects overview and one page each for NeuroCore, Argus ACLI and Argus Lab.
- `knowledge-base/`: the Knowledge Base index and one folder per category. A category's `index.html` is its landing page; focused articles sit beside it as named `.html` files.
- `glossary/`: the single Glossary page, which is also where inline glossary tooltips link to.
- `story/`: the origin story page.
- `blog/`: placeholder folders, one per planned Blog category. They hold `.gitkeep` files only. No public Blog pages exist.
- `assets/images/branding/`: logos, one folder per project (`tensa`, `neurocore`, `argus-acli`, `argus-lab`). Which logo goes where is in `docs/website_state.md`.
- `assets/images/social/`: the social preview image.
- `assets/images/blog/`: placeholder folders for future Blog images, one per category.
- `assets/js/`: `glossary-tooltips.js`. Glossary links still work as plain links without it.

## Not published

Kept off the site by the exclude list in `_config.yml`.

- `_config.yml`: the exclude list itself.
- `README.md`: what the repo is, its direction, how to resume, and the keeping-it-small rules.
- `docs/ai-operations/`: the resume note, the operating rules and the closeout pointer. `claude/` holds the prose-polish prompt.
- `docs/planning/`: the planning docs. What each one owns is in `docs/planning/documentation_strategy.md`.
- `docs/infrastructure/`: this map.
- `docs/website_state.md`: branding, deployment facts and open decisions.

## Planned, not created

- `resources/` and `build-notes/`: future public sections.
- `scripts/`, starting with `scripts/check_internal_links.py`. It is internal, so it joins the exclude list in `_config.yml` before it reaches `main`.
